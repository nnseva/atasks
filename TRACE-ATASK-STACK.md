# Техническое задание

Для упрощения отладки, при обработке исключений нужно иметь возможность получать и анализировать стек вызовов между отдельными atask.

Даже если atask вызывают друг друга через сеть, при обработке исключения должна быть доступна информация - какие atask вызывали друг друга, вплоть до корневого вызова.

Реализация должна поддерживать формирование стека, начиная с корневого асинхронного вызова. В информацию фрейма atask, так же как для обычных фреймов, не включаются параметры вызова.

Структура фрейма atask предположительно (реализация на усмотрение исполнителя):

```
class AtaskHop:
    seq: int                 # позиция от корня (0 = самый первый вызов)
    call_id: str              # uuid4 этого конкретного вызова
    task: str                 # имя atask, как в registry
    namespace: str
    kind: str                 # 'rpc' | 'queue' | 'broadcast'
    caller_file: str          # где стоит await some_task(...)
    caller_line: int
    caller_func: str
    host: str                 # идентификация хоста - см. ниже
    pid: int
    ts: float
    await_frames: tuple = ()          # фреймы обычных await до обращения к atask
```

Имя хоста либо задается явно при конструировании Router, либо конструируется автоматически, неблокирующими вызовами операционной системы. Один из кандидатов - hostname (без обращения к резолверу). Уникальность имени хоста обеспечивается со стороны ответственного за развертывание. Для поддержки со стороны библиотеки, в `run.py` добавляется параметр hostname, а в Router - соответствующий именованный параметр вызова.

Пояснение: чтобы конструктор Router получил имя хоста и другие параметры, пользователю бибилиотеки нужно вызвать конструирование Router до первого прямого или косвенного вызова get_router(), после чего get_router() будет возвращать этот экземпляр Router. Сама функция get_router() не меняется.

В await_frames по умолчанию включаются все await frame без фильтрации (то есть в том числе, фреймы самой библиотеки atasks). Фильтрация фреймов библиотеки atasks и других служебных библиотек (например backoff) включается необязательным параметром Router - который задает список имен модулей, подлежащих исключению из await_frames. Еще одним необязательным параметром Router является флаг, исключающий сбор await_frames - таким образом, в стеке остаются только фреймы atask.

Если функция вызвала `atask` и обрабатывает полученное исключение, это исключение должно позволить проанализировать:
    - стопку вызовов, `atask` и обычных `await`, которые привели к вызову данной функции (то есть вышестоящие вызовы)
    - стопку вызовов, `atask` и обычных `await`, начиная с данной функции и заканчивая кодом, бросившим исключение (то есть нижестоящие вызовы) 

Когда исключение обрабатывается декоратором `atask` (то есть в коде `_on_message`, исключение обработанное на стадии `_call_coro` приходит туда в составе возвращаемого значения), это исключение как и раньше, передается на вызывавшую сторону вместе с собранным стеком вызовов atask. 

Если исключение доходит до обработчика `atask_queue` или `atask_broadcast` (то есть в коде `_on_event_message` и `_on_broadcast_message`), то исключение терминируется выводом полного собранного трейса, вместо logger.error.

Полный собранный трейс выводится наподобие обычного трейса, в котором фреймы atask выделены специальными отметками (например декоратором, соответствующим kind), облегчающими чтение трейса, и снабжены дополнительными параметрами, сохраненными в фрейме (call_id, task, namespace, kind, host, pid, ts - в человекочитаемой форме, например YYYY-MM-DD hh:mm:ss.sssZ) - окончательный формат на усмотрение исполнителя.

Совместимость протокола можно не соблюдать - пакет находится в стадии разработки и нигде пока не развернут.

Имеет смысл добавить контроль глубины стека вызовов atask и установить предельную границу в параметрах конструктора Router (по умолчанию 1000 - только atask фреймов).
